## Разрешение и границы

Бэла явно согласовала проверку памяти перед камерой, подтверждение фактического
сохранения первого файла, повторную отправку того же снимка без камеры и
предупреждение до помещения денег в сейф, если фото ещё нигде надёжно не сохранено.
Проведение РКО/ПКО независимо от передачи фото. Нет новой миграции, правок1С,
реальных финансовых тестов или новых ADMIN-уведомлений. Не изменять график,
чек-листы, payroll/OFD и финансовую политику автоматических повторов.

Найденный дефект1.21.24: отказ IndexedDB переключал отправку на multipart;
при последующем сетевом отказе input уже очищен, а исходный File не удерживался.
Снимок можно было потерять даже без перезагрузки. Старый тест проверял лишь
отсутствие ложного сообщения об успешном сохранении, но не сохранность файла.

## Реализация и отличия от согласованного1.21.24

- Существующая IndexedDB-очередь сохранена. Перед камерой — неблокирующая
  проверка транзакции и запрос браузеру на persistent storage. Маленькая проба
  не считается доказательством сохранения большого снимка.
- Перед первым await исходный принятый файл удерживается в модуле приложения.
  После записи читается именно сохранённый Blob, проверяются размер и SHA256.
  Только тогда UI может говорить «Фото сохранено на телефоне».
- При отказе диска первый файл остаётся в открытом приложении, доступен после
  закрытия формы/возврата в компонент и при повторе сохранения/отправки.
  Это RAM, не обещание пережить перезагрузку/выгрузку процесса iOS.
- Даже в этой ветке штатный v2 metadata-first не ждёт сетевой загрузки фото.
  Финансовый UUID, сумма, исходный день и hash снимка не меняются.
- На реальный отказ сохранения UI предупреждает «Фото не сохранено.
  Не кладите деньги в сейф» и показывает повтор исходного снимка. Прочие задачи
  не блокируются; beforeunload просит браузер защитить случайную перезагрузку.
  iOS может не вызвать это событие, поэтому это дополнительная защита.
- Само отсутствие связи не вызывает такое предупреждение: сохранённая очередь
  переживает обычную перезагрузку. Online/возврат в видимое приложение инициирует
  немедленную попытку с исходным ключом; скрытое приложение не делает запросов.
- Зависшие операции IndexedDB ограничены по времени. Неудачное чтение больше
  не обнуляет отображаемую очередь. Финансовый retry-policy не менялся.
- После точного серверного подтверждения полного фото очередь очищается.
  Метаданные суммы сами по себе не подтверждают фото. Аварийный фото-first
  переключатель сохранён. Полная ошибка диска не заставляет повторять съёмку.
- Кнопка повтора в общей плашке стала компактной иконкой с прежним доступным
  именем: на390px текст больше не зажат в узкий столбец. Смысл действия сохранён.

Невозможно обещать сохранение в любом случае при отказе всей памяти телефона,
отсутствии сети и завершении процесса. Хранилище браузера может отказать или
быть очищено. Подтверждённое локальное хранение и RAM явно различаются.
Справка WebKit: https://webkit.org/blog/14403/updates-to-storage-policy/.
Нельзя выдавать запрос persist() за гарантированное разрешение.

## Повторный аудит по просьбе владельца, 2026-11-04

В рамках защиты первого снимка дополнительно исправлены:

- Запоздавшее чтение IndexedDB могло восстановить уже отправленное фото в
  очереди. Подтверждённые ключи больше не возвращаются из старого чтения;
  более новое состояние в памяти не перезаписывается.
- При повторном открытии компонента React счётчик ещё мог быть0 при RAM-only
  фото. Auto-update теперь проверяет наличие удерживаемого файла напрямую.
- Блокировка отправки устанавливается до чтения/хеша файла: повторное нажатие
  не создаёт вторую отправку. Ошибка изображения освобождает форму и ничего
  не проводит. Прежние JPG/PNG/WebP и8МБ сохранены.
- Восстановление локального хранения повторяется и без сети, независимо от
  backoff сетевой отправки. Успешная проверка файла снимает предупреждение
  о памяти; финансовых запросов офлайн нет. Устаревший preflight не переносится
  в новую форму и снимается после реальной успешной записи.

Регрессии сначала воспроизведены тестами прежнего кандидата, затем исправлены.
Отдельно проверены два зависания IndexedDB: ограниченное ожидание и закрытие
позднего соединения, без ложного подтверждения сохранения.

На3223 внешний тестовый скрипт перед запуском настоящего PWA подставляет отказ

загрузки. Реальные React-компоненты сами обрабатывают эти условия, их состояние
не подменяется. При восстановлении сети отправляются штатные online/offline
события. Контроль fault-стенда служит только локальному воспроизведению.

Показаны: отсутствие связи до камеры, подготовка снимка, сохранённый офлайн
снимок, подтверждение суммы при неполученном фото, дозагрузка, завершение,
preflight-отказ памяти, одновременный отказ памяти/связи, прежний отказ файла
больше8МБ и восстановление памяти без интернета. При восстановлении памяти
первый удерживаемый файл сам сохранился, без нажатия и без новой съёмки.
