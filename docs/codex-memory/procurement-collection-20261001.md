## Правило и интерфейс

Только проведённая native-заявка «К оплате», операция «Оплата поставщику»,
наличные RUB, точный заказ и поставщик, одна подходящая утверждённая CASH-заявка
портала среди ВСЕХ менеджеров. Не подбираем по совпадению суммы/даты.
Весь остаток разрешения должен помещаться в неоплаченный остаток портала.
Дубли, противоречия, неполное исполнение/РКО, неоднозначные распределения и
несколько действующих разрешений не дают приглашения за деньгами.

Опциональное evidence.collection не участвует в зачёте оплаты. Сумма исполнения
и остаток подтверждаются регистром и связанными РКО. Обычный прямой РКО также
учитывается существующим общим matcher и снимает приглашение при полной оплате.
Частичное исполнение показывает только остаток. Подотчёт и валютные оплаты
новое правило не переопределяет. Заявки без заказа этим путём не сопоставляются.

Один общий компонент внутри существующей карточки:
«Получить 2 октября · 68 000 ₽ / Касса Хурзокова»; в день выдачи —
«Можно получить 68 000 ₽». ADMIN видит тот же блок; никакой новой кнопки выдачи.
При неполных источниках или неподдерживаемой сверке RUB приглашение скрыто.

## Уведомления

Существующий минутный dispatcher создаёт procurement_collection_ready;
ключ native request + portal plan + user, createMany skipDuplicates.
Никаких очередей из GET. Повторная сверка текущей версии плана и активности
сотрудника перед отправкой. Общий in-flight read с закрытием старых уведомлений.
22:00–08:30 Москва — перенос, утром повторная проверка; полная оплата/отмена
снимает уведомление, недоступный источник откладывает и не объявляет оплату.
CAS и восстановление uncertain-send аналогичны действующему подотчёту.

Системный push нейтральный («Деньги для оплаты»), чтобы отложенная ОС доставка
не показывала устаревшее разрешение/сумму. Колокольчик и календарь показывают
свежую сумму, кассу, дату и поставщика. При недоступности источника в колокольчике
нейтральная подсказка. Факт приёма push провайдером не гарантирует его показ ОС.
Один native-документ не порождает повторные пуши при каждом обновлении/частичном
РКО; повторно открытое уже отменённое уведомление автоматически не рассылается.
